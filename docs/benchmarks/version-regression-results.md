## 固定流程与 Agent 的调用取舍

同一套 6 个 HTTP 模拟场景逐一运行两个策略，包括完整校验失败/超时、未知错误、规则冲突、伪造引用及预算不足。全部失败和未决任务保留。

| 指标 | 全部 Agent | 混合策略 |
|---|---:|---:|
| 任务尝试 | 6 | 6 |
| 有效结构化报告 | 4 | 4 |
| 拒绝/失败 | 2 | 1 |
| 未决、人工复核 | 0 | 1 |
| 实际 HTTP 模型调用 | 10 | 7 |
| 平均调用/任务 | 1.667 | 1.167 |
| 模拟 token | 300 | 210 |
| 模拟服务整任务 P95 | 12.399 ms | 1.729 ms |

[完整调用与证据记录](2026-10-13/ci/hybrid-fixture.json)。实际调用降低 30%，这里只证明相同功能场景下的分流与引用约束行为；脚本化模型不具有真实诊断质量，不据此声称“同等根因效果降低成本 30%”。该场景数量也不足以支撑稳定的时延分布结论。

真实供应商的新策略对照尚未运行：当前会话无私有模型密钥，也无可审计计价信息。真实费用记为未知/null，不用合成 token 或预留预算推算账单。已提供留出集 `-mode agent/-mode hybrid -heldout` 对照入口及全任务平均调用/时延/P95记录；原有 ITBench 中 Agent 低于单次调用的结果仍保留，见[历史质量评测](results-2026-10-12.md)。

## 跨实例故障注入

两个存活 Worker 和两个被 SIGKILL 的独立进程，使用同一真实 PostgreSQL；12 个任务，50 次初始计划投递，接管/容量延后产生的尝试不冒充只投递 50 次。每第五次模拟供应商请求返回 429，检查点、执行代次和结果/outbox 持久化均走生产代码。

| 指标 | 实测 |
|---|---:|
| 最终完成 | 12/12 |
| 最终结果丢失/重复 | 0/0 |
| 持久化检查点/完成事件 | 12/12 |
| 实际模型 HTTP 调用 | 17 |
| 注入 429 | 3 |
| 两次被强杀后额外调用 | 2 |
| 共享并发上限/供应商观测峰值 | 2/2 |
| 接管 P95 | 30.062 s |

[原始测量](2026-10-13/ci/shared-quota-multiprocess.json)。17 次调用对应 12 次最终任务调用 + 2 次被打断调用 + 3 次 429 重试。接管样本数仅 2，分别 30.045/30.062 秒，主要受 30 秒任务租约约束；不称为生产 SLA。测试中的请求上限为 2 秒、崩溃宽限为 200 毫秒；默认配置为 60 秒与 30 秒，因此不能把测试回收速度直接外推到默认配置。

许可覆盖客户端调用生命周期，不保证供应商断连后立即停止计算；数据库会话丢失与忽略取消的客户端组合不在严格峰值保证内。外部响应—检查点提交间隙仍可能重复计费。
