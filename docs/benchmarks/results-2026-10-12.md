# Argus Agent 评测报告

日期：2026-10-12。运行实现冻结于 b290fbebc39fd2c80223af64c4b9883c694cca02。

三个运行机制演示验证通过，但当前 Agent 的专业 SRE 根因评分低于单次调用基线。没有生产规模或诊断效果提升的证据。

## 公开专业 benchmark

IBM ITBench-Lite，Apache-2.0，数据版本 d0916b08ba421ce5e672e9ad68aa947d938dfef0；官方评分器 14f026fc9cc348c4ecec5ab32714de954c95c1b1。
来源：https://huggingface.co/datasets/ibm-research/ITBench-Lite
评分器：https://github.com/itbench-hub/ITBench-Evaluations

开发集为编号最小的 10 个 SRE 场景，3 次 Agent 试验/场景；另预选 13、14、15、16、17 为留出集，各 1 次。单次调用基线分别运行 10 次与 5 次。真值未进入模型输入，预测完成后才交给评分器。
输入为告警、Warning K8s 事件及最新 otel-demo 资源快照；缺少指标、应用日志与链路追踪。因此这是适配式离线迁移试验，不是官方排行榜成绩或 OTA 准确率证明。

| 组别 | 有效报告 | 官方实体 F1 | 补零统一分母 F1 | 官方解释得分 |
|---|---:|---:|---:|---:|
| 开发基线 | 10/10 | 0.2813 | 0.2532 | 0.4000 |
| 开发 Agent | 29/30 | 0.0111 | 0.0111 | 0.0333 |

官方开发基线 F1 的有定义场景为 9/10；补零列统一将缺失值按 0 计入，避免选择性剔除失败。所有重跑、失败及原始评分保留。同模型 judge 可能误判；严格 namespace/kind/regex/alias 检查作为补充，其结果在 *entity-check.json 中，不是官方评分。

## 失败分析

- 初版 30/30 未完成报告；上下文归档、工具分页和运行预算修复后，开发集 29/30、留出集 5/5 产出报告。这个变化只证明结构化报告产出能力，不证明根因准确率提升。
- 最终仍有 1 次预算耗尽。它被保留并计入所有分母。
- 多个 Agent 结果把 data-recorders、kube-system 的背景故障当作业务事故根因。下一步需要事件范围、时间窗口、依赖与因果关联检查，以及补齐遥测。
- 有效报告、实体定位、根因解释、运行恢复是不同指标，不能混成一个“成功率”。

## 三个运行演示

1. 真实 DeepSeek 3/3 引导式合成案例观察到初始假设被反证修改。初始假设由模型仅根据历史案例生成，当前日志在后续调查提供；案例包含明确物理观测，不能外推到生产。
2. 实际子进程以退出码 77 在提交工具 checkpoint 后结束，再启动恢复已完成工具前缀与累计预算；PostgreSQL fencing 由独立集成测试验证。不是整套生产部署的断电恢复验证。
3. 并发与队列有界、429 重试有界、等待/退避/HTTP 可取消；队列满转任务延后且不消耗调查预算。限制作用于单进程，不是全局租户配额。

## 本地 HTTP 控制压测

硬件：Apple M4 Pro / 14 核 / 24GiB RAM，macOS 26.5.2，Go1.24.12 arm64。32 客户端，每组 1,000 次逻辑请求；控制服务每次尝试延迟 5ms，每第 7 次尝试返回 429。

| 配置 | 成功 | P95 | 尝试次数 | 峰值执行并发 |
|---|---:|---:|---:|---:|
| no_retry_c2 | 858/1000 | 99.740ms | 1000 | 2 |
| retry_c2 | 1000/1000 | 119.430ms | 1166 | 2 |
| retry_c8 | 1000/1000 | 35.153ms | 1166 | 8 |

2 并发下，成功率增加 14.2 个百分点，P95 增加约 19.7%，供应商请求尝试增加 16.6%。这是一次控制实验，没有置信区间；有限重试不能保证所有负载下 100% 完成。控制服务的 Token 是合成值，不是付费 API 用量。

## 数据与复现

agent-evaluation-summary.json 包含版本、逐组运行、失败、评分、回归、真实反证演示与压测记录。数据 manifest 保存源文件路径、长度、SHA256。归档包保存原始 benchmark 输入、真值（仅评分用）、盲化输入、全部版本的预测与评分、日志、回归记录和源码。私钥不进入报告或源码。

生产限制：parser/aggregator 仍有 mock；无生产 SLA、真实客户规模或业务收益验证。升级 checkpoint v3 前需用旧 worker 排空 v1/v2 未完成调查；外部响应—checkpoint 的间隙可能重复计费，不宣称 exactly-once。
