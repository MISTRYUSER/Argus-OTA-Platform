# OTA 故障现场回放评测（A）设计

用户目标：在 PR #11 / main 847c4a4 的基础上，先验证真实模型的调查质量与开销；本轮只实现 A，并准备 B 的可核查发布清单。复用 agent-bench 和生产调查/混合执行，不增加 Agent 数量或分流规则。

## 范围与来源

本地 Python HTTP 下载服务及延迟代理实际运行，产生原始客户端/服务端日志、请求次数和延迟；不是直接编辑统计值。六个原因：客户端超时过短、服务端变慢、网络延迟、失败后的错误重试放大、发布清单错误、下载产物损坏。每种原因各一个开发和一个预先划分留出场景，参数不同，共 12 场景。保留无关心跳、无关近期变更；这些是受控实验，不是生产事故。

每个故障包 public 保存实际日志、配置差异、依赖关系、指标、版本清单和输入；private 在本地保存注入内容、正确原因、关键证据组与恢复条件，禁止上传公开仓库或 CI 产物。准备器不读取 private。输入不包含原因标签/注入选项，场景 ID 不透露原因。评分器单独读取 private；模型工具只能读取 public 适配结果。

## 版本证据

生成临时真实 Git 仓库，提交配置与下载服务源码，记录基线/当前提交、树中配置 blob、配置 SHA256、实际产物 SHA256。发布声明与实际计算哈希分别保存；时间为本地实验记录，不能宣称真实车辆部署。B 的生产变更/依赖查询及 PostgreSQL 表不在本轮。

## 三策略及测量

baseline：确定性取证全部适配行+代码统计，单次总结；hybrid：原生产 Eligible 与固定分支+调查；agent：原生产多轮调查。模型、最大上下文 24000 字符、模型预留预算 1000000、最大 12 步、180 秒任务超时、供应商重试策略保持一致。默认沿用 DeepSeek，但模型名/endpoint/预算显式配置，结果记录请求模型及供应商返回模型。固定流程的能力边界不得暗改。

扩展现有入口的 OTA 任务说明、数值 ID、输入 SHA 校验和预检命中率。OTA baseline 引用统一 log:N 和 stats:CODE，不泄露评分答案。根因额外要求 cause_code，评分仅认主因字段；不靠自由文本关键字“提到答案”计分。所有分支收到同一原因类别表（任务契约），评分真值不进入提示词。

全量 scheduled case/trial 评分，缺结果也记失败；未决单列。统计根因正确/错误/缺少明确原因、证据已获取/已引用/完整使用、取证不足与推理错误、调用/重试/用量/费用/P95。费用仅在实际 HTTP 响应用量完整且提供版本化价格表时按缓存命中/未命中/输出用量计算；这是使用量估算，非账单。缺用量/价格保持 null，不删除失败。

## 验收与限制

测试固定分支命中与 Agent 覆盖、同症状不同原因、无关提交、private 改动不改变 public 输入、证据位置与 SHA 一致、失败/未决/缺失纳入分母、收费字段缺失不归零。实际运行故障包同时记录健康控制和恢复条件检查，证明注入确实影响运行；这不等于 Agent 受控修复验证（C）。

真实模型运行需要现有供应商密钥；没有凭据时只交付可运行入口及明确的 pending 状态，不能宣称新策略质量或费用改善。历史 SRE 数据可用 -preflight-only 检查，未下载的不声称已经计数。
